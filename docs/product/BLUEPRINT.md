## 最新方向適用範圍

使用者最新補充：角色不一定五人，可能依付費意願調整，並詢問免費玩家是否只給一人。因此，本文件既有「五人／五角色」描述保留作為早期設計基準，不再代表固定名額或免費取得五人的承諾。角色數、解鎖與付費制度以第 8 節待驗證方案為準；產品核心仍是家族分工、離線進展、冒險與玩家互動。此輪只有規劃，不代表啟動收費或開發。

## 1. 產品定位

**家族經營，離線分工，帶著成果去冒險與交易。**

玩家每天用幾分鐘安排家族成員，離線期間採集、製作或探險；回來看見可信、可理解的成果，再決定家族下一步。不是先重做完整 MMORPG，也不是只有產量上升的放置工廠。

首要客群假設是喜歡童話式幻獸、成長與生產，但不想長時間掛著電腦的成年懷舊玩家。這是假設，應透過訪談與封測確認；「家族」不自動代表親子／兒童產品。

### 三個核心支柱

1. **分工有選擇**：五個角色有限時間，在採集、加工、旅行與冒險間取捨，不是五倍重複點擊。
2. **生產有用途**：工具、裝備、補給與交易需求連起來；產出能改善下一次安排，而非只堆倉。
3. **離線可信任**：關閉網頁、重啟服務、重送指令都不會吞成果或重複發獎；停工原因清楚。

### 保留原始願景，提出待驗證的交付順序

五角色、無職業鎖、熟練度、幻獸、連擊／轉移目標、路徑移動與未來圖像觀察均保留。本輪建議先用最小可玩閉環驗證家族管理，再加深戰鬥與社交；這是待驗證的拆分提案，不是使用者已定案的優先序。官方整合不作為近期依賴或承諾。

### 願景補充：不能在精簡 MVP 時消失

- 五角色可以分開工作，也能組成自己的家族隊伍冒險；首版簡化遠征是通往組隊冒險的切片，不是永久改成純生產遊戲。
- 持續工作的主體是常駐遊戲伺服器，玩家關閉瀏覽器或電腦後仍進展；開發代理、排程提醒與本機開著網頁均不能替代它。
- 先用低成本、可讀易操作的文字介面驗證興趣。未來可選擇觀察與原版對應的地圖、角色及戰鬥畫面；須先釐清素材權利與對應資料，不承諾像素級還原，且不以開啟畫面作為進度條件。
- 未來經官方明確授權的外掛／整合保留為長期探索。未取得授權不開發或部署官方客戶端控制；不預作封包、繞過限制或連線整合，不把授權當成已取得。

## 2. 核心循環與第一次遊玩

**設定家族目標 → 分配角色與材料 → 移動／工作／小型遠征 → 離線執行 → 回訪摘要 → 使用或交易成果 → 調整分工。**

建議首個目標：「做出能改善採集的工具，並準備一次小型遠征」。

- 初始角色數與解鎖方式待測，參見第 8 節；新手引導逐步教分工，不把單角色體驗當成家族玩法已驗證。
- 一頁總覽五人的活動、預計完成時間、缺料／滿倉／停工原因。
- 安排採礦、冶煉、鍛造，保留一部分時間給旅行與遠征。
- 回訪顯示開始與結束時間、投入、產出、消耗、停止原因，而不只未讀日誌數。
- 產出立即有去處：工具升級、有限量 NPC 訂單、簡化遠征消耗。NPC 訂單是早期需求底座，不是無限印鈔機。
- 優先做批次指派、重複工作與清楚停止條件；不要求玩家頻繁上線領取才能繼續。
- 小型遠征初期只驗證派遣、風險與回報，可以使用家族版簡化規則；不等於完整戰鬥系統已完成。

### 經濟設計約束

五角色很容易完全自給自足，因此交易不能只靠「做一個市場」自然出現。以時間、工具、熟練度與產能取捨形成專長，不重新加職業硬鎖。初版至少提供兩種合理分工；單人可前進，交易讓安排更有效率，但不強迫社交。

每個產出都要標示用途、回收途徑與預期累積速度；金錢須同時有來源與消耗。品質、耐久、失敗率、離線上限先列待驗證參數，不同時堆上所有懲罰機制。任何離線上限需在安排活動前透明顯示，不能事後吞掉預期成果。

### 戰鬥設計約束

先做自己五人家族的非同步遠征，再考慮跨玩家隊伍。技能、武器熟練度、幻獸與裝備應產生不同解法，不讓單一角色包辦所有用途。連擊需有明確次數／資源預算、轉移條件與終止條件；範圍技的目標數與多段額度不得互相放大成無限追擊。動畫只觀察結算，不能決定回合或掉落。

**待驗證玩法提案，而非已定案數值：**

- 自由技能：角色可學習／使用各系技能，對應武器與熟練度提供效率差異；先比較跨武器施放與專精收益，避免所有角色最後都使用同一套最強技能。解鎖、傷害、MP 與成長速率仍待測。
- 擊倒追擊：先以「單體技能擊倒目標後，於同一行動剩餘額度內轉移到下一個合法目標」作為原型方案；未擊倒不自動取得無限續連。最多追擊次數、傷害遞減、額外 MP、無合法目標時終止，以及技能內建多段如何共用額度，都需明確定義再測試。
- 範圍技能以最大目標數及總攻擊額度共同約束，不把每個擊倒各自展開一條無上限追擊鏈。M3 需對單體、範圍、內建多段、擊倒與無目標做組合驗收。

## 3. 範圍與技術方向

### 建議的 M1 可玩切片（非已定案的公開首版範圍）

帳號與五角色、共用倉庫／金錢、單一村莊與少數地點、路徑旅行、一條生產鏈、工具用途／有限 NPC 訂單、最小遠征、持久化離線活動與回訪摘要。建議先檢查一個人有理由回來，再驗證兩個家族互相需要；是否將最小社交切片與 M1 同期交付仍待決定。

### 建議後續擴充與待定時機

兩帳號交易先於大型市場；簡單文字聊天只有在具備節流、檢舉與處理機制後才開放。完整幻獸與戰鬥深度、跨玩家組隊、代工契約、圖像觀察、公會、世界首領與大地圖逐步評估。遠期官方整合不預作控制或封包功能。

### 最小可信架構提案

採簡單的 TypeScript 模組化單體、交易式資料庫與持久化活動／到期事件，不先做微服務。實際選型在 M0 驗證與記錄。

- 伺服器時間與狀態為準；不信任客戶端時間、物品或獎勵數值。
- 活動記錄起訖、角色、投入、版本與停止條件；扣料／保留料／產出有一致性。
- 指令帶冪等鍵，活動改派使舊事件失效；同一角色不得同時出工與探險。
- 使用可追查的資源流水；重啟後從持久化資料恢復，不依賴瀏覽器或永久記憶體計時器。
- 純規則、伺服器指令與文字 UI 分離，讓未來圖像只讀同一狀態與事件。
- 複用前逐項查來源、權利、依賴與限制。原版提取、推測、示範、自訂不得混標；來源資料名稱不作為正確性證明。
- 私有來源的詳細審查保留在適當私人管道；公開 repo 只收可公開且有權使用的內容與摘要。

## 4. Milestones 與退出門檻

以下是本輪提出的驗證順序與依賴假設，不是使用者已批准的排程，也不是日曆承諾。

**社交與玩家互動是核心目標，不是可無限延後的附加功能。** README 的初始清單把交易與聊天放進首版；本藍圖暫將家族切片列 M1、跨家族交易驗證列 M2，是為拆開風險而提出的不同方案。M1 僅證明個人家族閉環，不能當作完整社交 MVP 或整體產品驗收。最小社交是否併入 M1、聊天與交易是否同期、公開首版應涵蓋哪些門檻，需在 M0 形成明確決策，未決定前不得把本排序當作開發授權。人力、預算、資產可用性尚未確認，不虛報完成週期。各階段須留下版本、測試證據與未驗證項目；前一門檻未過，不以更多內容掩蓋問題。

### M0：把風險與最小規格釘清楚

交付：產品範圍、五角色總覽流程、資源來源／用途表、可複用模組與權利清單、活動結算技術驗證。此輪文件只是 M0 的規劃部分，並未完成技術驗證。

驗收：
- 每種初版產出至少有一個用途或合理回收方式。
- 明確標示沿用、自訂、未知，不把缺資料當已完成。
- 確定離線上限／停止／取消／改派語意與新手防卡死規則。
- 以可重現案例證明離線、重啟與重送的結算設計可行，才進 M1。

### M1：第一個值得回來的五人閉環

建議交付：第 3 節 M1 可玩切片所列功能；重點是一個玩家玩得通，不是功能清單打勾。此階段不宣稱已驗證社交價值。

驗收：
- 新玩家在 10–15 分鐘內完成第一個有用製作，能說出下一個家族目標。這是待驗證設計目標。
- 至少兩種分工安排合理，不只有唯一指定流程。
- 關閉瀏覽器後仍按伺服器時間進展；重新登入、服務重啟及重送都不重複扣料／產出。
- 缺料、滿倉、取消、改派時結算一致且理由可見；新手不能進入無法恢復的資源死局。
- 客戶端改時鐘、越權操作及重播指令不能取得資源。
- 記錄程式檢查與真人介面驗收，分別報告。

### M2：兩個家族真正互相需要

交付：簡單掛單市場、交易紀錄、兩種互補需求、金錢回收與濫用防護。聊天不是市場驗收的前置必需品。

驗收：
- 兩買家競購最後一件只成交一次；取消與購買競爭不導致物品或金錢複製。
- 賣家、買家與第三帳號權限隔離；不可跨帳號更改庫存或訂單。
- 邀請 5–10 位目標玩家，至少一半完成對雙方有用的交易，且不是管理員送物資製造需求。此門檻是探索性提案。
- 無人交易時單人仍能合理前進；觀察物資累積、資金來源與消耗，不只成交量。

### M3：遠征、技能與幻獸形成深度

交付：2–3 條戰術路線、幻獸取得／培育／用途、有限連擊與轉移目標、遠征對生產物的持續需求。

驗收：
- 至少兩種家族配置可行，玩家能理解風險與結果差異。
- 撤退、取消與失敗成本事先可見；工作與遠征不能重疊佔用同一角色。
- 連擊、範圍、多段與 MP 消耗有可測上限；不出現無限循環。
- 回放、動畫速度、斷線與重連不影響掉落、回合或結算。
- 不以大量新地圖代替戰術選擇。

### M4：小規模封測，驗證是否值得擴張

交付：20–30 位目標玩家、7–14 天封測、入門／回訪／交易觀察、訪談、備份恢復與營運診斷。

探索性門檻：
- 70% 完成首個核心循環；第七日 40% 自願回訪。樣本很小，這些是內部討論門檻，不是統計結論或已達成數字。
- 訪談能指出自主目標與回訪理由，不只有「被提醒上線」。
- 做一次備份恢復演練；資源異常可追查；資料遷移不破壞活動與帳號隔離。
- 不達標先修循環、引導與經濟，不自動新增內容或擴大招募。

### M5：公開測試與商業可行性

依封測證據決定圖像觀察、有限合作契約與更多內容的先後。公開前驗證素材與品牌使用範圍、隱私／社群處理方式、實測容量與單位成本。商業模式依第 8 節比較額外角色與同活動上限方案，也保留外觀／支持型收入。付費增加並行活動會帶來產能與交易優勢，必須量測其對免費體驗及經濟的影響；尚未決定商業模式或價格。

驗收：容量有測量基準、預算有上限、回復流程可執行、社群與支援有人負責、使用權利清楚，且前四階段有可追溯證據。沒有這些不宣稱可公開營運。

## 5. 風險與決策紀錄

| 風險 | 處理方式／驗證 |
| --- | --- |
| 五角色變五倍家務 | 一頁總覽、批次指派、回訪摘要；觀察操作時間而非只看功能存在 |

| 來源可讀但不可公開重用 | 權利與來源逐項審查，不搬運私有內容 |
| 過早做畫面與大型世界 | 先過 M1–M4 門檻；文字 UI 仍需可用性 |
| 經濟／留存未知 | 小樣本試玩與訪談，不宣稱市場已驗證 |

- 保留原始構想；本文件不刪除長期需求、不改寫為已完成。
- 工作週期、離線上限、品質／耐久、技能傷害、連擊額度與部署預算仍待定。
- 下一個有界工作是補齊 M0 規格與技術驗證，不是直接開發全部藍圖。必須另行安排執行；本輪到文件交付為止。

## 8. 角色數與商業模式：待驗證方案

### 使用者方向與 PO 建議分開

**使用者已改變的前提：** 不一定固定五人，可探索付費意願與角色數的關係。使用者是在詢問免費一人是否合適，並未決定免費／付費名額、訂閱或價格。

**PO 建議：** 不把免費一人當長期預設。家族分工是核心賣點，只有一人容易變成「排一件事然後等待」，也無法體驗同時採集與加工的取捨。單角色可作極短的新手教學或對照實驗，不應讓玩家先付錢才知道遊戲好不好玩。以下數字均為試驗方案。

### 方案 A：免費 2 人起，進度解鎖第 3 人；付費最多 5 人

- 免費玩家一開始有 2 人，透過可達成、清楚可見的早期遊戲目標取得第 3 人，不把解鎖拖成付費壓力。
- 第 4、5 人可探索付費取得；一次買斷或訂閱尚未選定，不預設價格，也不以堆疊購買突破上限。
- 免費組可完成完整生活鏈、合理難度遠征與交易，不要求付費角色才有資格接觸核心內容。
- 遠征隊伍名額須與生產活動名額分開定義；不能一邊宣稱只是生產便利，一邊讓付費隊伍因多兩人直接壓倒免費隊伍。
- 若所有角色都能同時活動，付費玩家就有更多採集、加工與遠征機會，亦有壓低成本、壟斷供給與交易套利的優勢。以名額粗估，5 人相對 3 人是 1.67 倍並行槽位，相對 2 人是 2.5 倍；這不是實測產量倍率，實際仍受材料、旅行與其他瓶頸影響。
- 因此這是**付費產能方案**，不是「純外觀」或「沒有優勢的便利」。若採用，必須明確告知，不能以文字包裝掩蓋。

### 方案 B：可持有更多角色，但所有玩家同時活動上限相同

- 免費與付費皆以相同數量的活動槽位運作，例如同時 3 人；額外角色提供替換專長、外觀、收藏與不同隊伍配置。
- 付費仍可能因專精覆蓋更廣而獲得優勢，不宣稱完全零優勢。需測量切換成本、熟練度和預置配置是否形成隱性產能提升。
- 此方案較能保護交易經濟，但付費吸引力可能較弱。可搭配外觀與支持方案，不以故意增加免費操作負擔來製造便利需求。
- PO 傾向先比較此方案與 A，再決定是否值得用市場公平性換額外產能收入；不能只看短期付費率。

### 若採訂閱：到期不刪資產、不扣住成果

訂閱只是可評估收費形式，不是已採用模式。若測試訂閱：
- 角色、裝備、熟練度、幻獸、倉庫及已賺取成果保留，不能因到期刪除或清空。
- 到期前清楚通知可用活動名額變化，讓玩家指定保留活動的角色；沒選擇時有可預期的預設，不追溯處罰。
- 已投入材料的單次工作／遠征可安全完成並領取；額外名額不再啟動下一輪無限循環。多步排程需明定哪些屬於已開始、哪些未開始。
- 超額角色進入可查看與可取回資產的休息狀態，允許將其裝備／物資轉回家族；不要求重新付費才能取回既有資產。
- 切換、退款、到期與重訂閱都須有一致結算，不能重複領取或損失投入。這些是待實作驗收要求，不是目前已支援功能。

### 多帳與經濟壓力

免費多帳可能比付費擴角更划算。角色定價不能建立在「每人一定只開一帳」的假設上。先規劃分析異常資源流、批量新帳、循環交易與機器化操作；不得只憑共用 IP 判定作弊或封禁同家庭玩家。交易開放條件、可交易資源、合理速率限制與反濫用措施需兼顧新手及正常社交，不以不透明處罰彌補經濟失衡。

### 有界試驗與門檻

M0 補上名額／活動槽／隊伍槽的分離規格、到期語意與成本模型；未做真金流前先以可撤回的原型權限測試。M1 比較免費 2 人起至 3 人是否讓玩家理解分工；M2 同時比較 A、B 的經濟影響，不能只測單人進度。

觀察項目：
- 首個有用製作與第 3 人解鎖所需時間、卡關與回訪原因。
- 免費玩家是否能自主完成目標、交易與遠征，或覺得必須付費才能正常玩。
- 各組每活躍玩家的淨產出、金錢淨流入、交易利潤與市場集中度；區分遊玩時間差與付費名額效果。
- 付費意願、可接受付費方式、每帳號服務成本與支援負擔；不將口頭願付視為實際轉換。
- 多帳模擬、角色切換、到期及重訂閱的資源一致性。

小樣本先訪談、再做有明確觀察期的比較；不宣稱已取得統計結果。若免費體驗退化、交易被付費產能主導或出現到期資產損失，先調整／停止方案 A，不靠提高付費價或增加更強付費內容掩蓋。正式收費、價格、名額與營運承諾需另作決策，本文件不啟用任何付費功能。
